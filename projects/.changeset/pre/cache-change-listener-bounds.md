The `client.cache.onChange` method now bounds the work each listener can hold, in both APIs. A listener whose calls never finished, such as one returning a promise that never settles or an Effect that never ends, kept one unfinished call per cache change without limit. A listener now has at most `concurrency` unfinished calls, 256 by default, and up to `maxPendingChanges` later changes, also 256 by default, wait in the order they were applied. A change arriving beyond that drops the oldest waiting change, logs a `cache.changesDropped` Warn with the observer's new `id` and how many changes it has dropped, and counts the drop in `diagnostics().counters.cacheChangesDropped`. Both limits go in the new optional second argument, `CacheObserverOptions`, and `{ concurrency: 1 }` handles changes one at a time in order. A limit that is not a positive safe integer, or an unknown key, throws `ConfigurationError` in the default API and dies with it in the Effect API. A synchronous listener finishes each call before the next change, so the limits never delay or drop its changes. Shutdown does not wait for unfinished listener calls, so changes still waiting at shutdown, including its final clears, are dropped and recorded the same way
