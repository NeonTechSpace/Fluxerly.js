Reaction pages show several pages in one message that people flip with ◀ and ▶ reactions, because Fluxer has no buttons. Call `ctx.paginate(pages)` in a prefix command, where only the command's author can flip by default, or `client.messages.paginate(channelId, pages, { users })` elsewhere, in both the default and Effect APIs. Pages are strings or `{ content, embeds }` objects. Adding or removing an arrow both count as a click, so the bot needs only Add Reactions and Read Message History, and `removeClicks: true` instead removes each click, which needs Manage Messages. Listening stops after `idleMs` (default 60,000) without a click and at most after `timeoutMs` (default 300,000), then the bot removes its own arrows and the current page stays. The result reports `idle`, `timeout` or `singlePage`, and failures and cancellation use the usual failure channel. The new `ctx.sendHelp()` sends the router's help as one message, or as reaction pages when it needs more than one page. So that pages started after connecting receive clicks, `gateway.ignoredEvents: "auto"` now always keeps `MESSAGE_REACTION_ADD` and `MESSAGE_REACTION_REMOVE`
