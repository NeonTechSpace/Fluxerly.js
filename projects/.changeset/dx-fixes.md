Behavior change: The default `maxPages` of an iteration now grows with `maxItems`, so a caller who sets only `maxItems` gets up to that many items. It is the pages `maxItems` needs at the page size plus 100 spare pages for short pages and skipped duplicates, instead of a fixed 100. For example, `messages.iterateHistory` with `maxItems: 10000` and the default page size of 50 used to fail with `PaginationError` reason `pageLimit` after 5,000 items and now reads all 10,000. This applies to `iterateHistory`, `members.iterate`, `members.iterateSearch`, `guilds.iterate`, `auditLogs.iterate`, `iterateReactionUsers`, `iteratePins`, `threads.iterateMembers` and `messages.iterateSearch`, whose pages stay capped at Fluxer's 400-page ceiling. The default stays finite, so a server that keeps returning short pages still ends with `pageLimit`. An explicit `maxPages` is used as given, including a value above or below the new default, except that `messages.iterateSearch` never reads more than 400 pages. Code that relied on the old default to stop a long scan early can set `maxPages: 100`

Behavior change: The `directMessages.open` and `directMessages.send` methods no longer clear every cached private channel when they start. A successful opening replaces only the cached snapshot of the channel Fluxer returns, because opening a conversation changes no other channel. The overlap rules change in detail. A read that started before the opening is still not stored. A read of another private channel that overlaps the opening can now stay cached, because the opening no longer clears the cache when it finishes. A conflict involving the returned channel evicts that channel, and a stale successful opening evicts only its own channel. A failed opening that was started still clears the direct-message cache, because its outcome may be unknown and no channel is known to evict. Invalid input, such as `open("bad")`, fails before the cache is touched and leaves it intact. Code that relied on the full clear can call `client.cache.clear("directMessages")` after the write

The `PaginationError` hint for reason `pageLimit` now tells callers to set `maxPages` explicitly or lower `maxItems`, and to narrow the filters of a message search, which reads at most 400 pages. It no longer suggests a larger `pageSize`, because the default `maxPages` shrinks as `pageSize` grows
