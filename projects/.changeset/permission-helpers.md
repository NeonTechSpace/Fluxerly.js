Permission and role helpers now cover cache-first reads, role rank, timeouts, partial overwrite changes and readable permission names, in both entry points. The `permissions.fetch` method takes `preferCache: true` (`PermissionFetchOptions`) to use enabled caches for the guild, member, roles, channel and a thread's parent and fetch only what is missing, while the default stays a fresh read. The `hierarchy.highestRole(member, roles)` and `hierarchy.canManageRole({ guild, actor, role, roles })` helpers (`RoleManagementInput`) check rank from held snapshots, and `members.timeoutState(member, { now })` reports `"none"`, `"active"` or `"unknown"` from `communicationDisabledUntil`. The `permissionBits.patchOverwrite(current, { allow, deny, inherit })` helper (`OverwritePatch`) changes named permissions of an overwrite and keeps every other bit, and `permissionBits.label(name)` returns Fluxer's English name for a permission

Behaviour changes to know about:

- Missing-permission hints and the `requirePermissions` guard denial now use Fluxer's labels instead of identifiers or split identifiers, such as "Manage community" instead of "Manage Guild" and "ManageGuild", "Use voice activity" instead of "Use Vad" and "Time out members" instead of "Moderate Members". Code or tests that match this text must change. The `details.requiredPermissions` field still holds `Permissions` keys
- The `requirePermissions` guard now decides through `permissions.fetch` with `preferCache`, so it shares one deadline for its reads. The command is denied only when the channel's permissions cannot be confirmed, meaning Fluxer sent a channel without its permission overwrite list, and the reply is "This command cannot confirm this channel's permissions", replacing "This command cannot check permissions in this kind of channel". Code or tests that match this text must change. Every other failure still fails the command
- A fetched community channel that is not a thread and comes without a permission overwrite list fails `permissions.fetch` with reason `response` on both paths, because Fluxer sends the list as an empty list when there are no overwrites. The failure has outcome `"unknown"` as other unusable responses of a read do, records `details.read`, `details.channelId` and `details.responseField`, and carries a hint. A cached channel without the list is fetched again. With `preferCache`, a closing client now fails a cache lookup with `ClientClosedError` outcome `"notDispatched"`, as fresh reads do
- The `channels.removePermissionOverwrite` comment now says that Fluxer requires `ManageRoles`, and a bot without Administrator can remove only an overwrite whose denied permissions it has all of
