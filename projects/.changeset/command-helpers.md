The `commands` namespace has two new helpers in both APIs, and the quoted parser and its rejections changed. The new `commands.suggest(name, candidates)` function returns the candidate closest to a misspelled name, using the rule behind the `suggestion` of `CommandUnknownName`: Case is ignored, one edit is allowed for names of up to four characters and two for longer ones, an adjacent swap counts as one edit, and the earliest of equally close candidates wins. It returns `undefined` when none is close and for an empty name. It agrees with the router for its default case-insensitive matching when given the registered names of one level, while the router also considers aliases and reports the command's own name for a near alias. The new `commands.parseArgument(token, descriptor, options?)` function converts one word with any built-in argument descriptor except `custom`, using the router's own grammar. It returns the descriptor's value type, `undefined` for a rejected word, and the descriptor's `default` or `undefined` for a missing one. The new `CommandArgumentParseOptions` type carries `guildId`, which `member` descriptors need. Invalid input to either helper, such as a bad descriptor, a non-string name or candidates that are not an iterable of strings, throws `ConfigurationError` in both APIs, like other registration misuse

`PrefixCommandParseRejection` and the `CommandParserRejected` outcome of `onUnmatched` have an optional `name`, the command name the parser read before it declined, as typed. The `commands.parseQuoted` parser sets it for an unclosed quote and a trailing backslash, a custom parser may set it, and the router passes it through, so a reply can say which command a syntax mistake was for. A name that is not command-name syntax is reported as a parser failure. Existing parsers and callbacks keep working, because the member is optional.
